# 로비 입장 구역 → 8명 전용 경기 서버와 멀티플레이 확인

## 현재 구조

```
Lobby Place (시작 장소, 광장·상점 자리·자유 탐험)
    └ 경기 입장 구역에 들어온 8명 → 8초 카운트다운
        └ Match Place의 새 Reserved Server → 8명 도착 → 대전
            └ 경기 종료 → Lobby Place로 복귀
```

로비 전체 접속 인원으로 시작하지 않습니다. 캐릭터가 광장 북쪽의 빛나는 입장 구역 안에 있어야 대기열에 들어갑니다. 한 구역의 대기열은 8명까지만 받으며 다른 사람은 계속 로비를 탐험할 수 있습니다. 구역을 벗어나거나 `대기열 나가기`를 누르면 빠집니다. 카운트다운 중 참가자가 바뀌면 새 8명 기준으로 카운트다운을 다시 시작합니다.

로비에는 스킨 상점·몬스터 도감·이벤트 공간의 설치 자리와 표지판을 마련했습니다. 실제 스킨 구매 기능은 아직 없습니다. 이 대기열은 한 로비 서버 내부의 구역 대기열이며 여러 로비 서버의 참가자를 합치는 글로벌 매칭은 아닙니다.

## 1. Studio에서 네트워크와 대기열 확인

1. **`Lobby.rbxlx`**를 Roblox Studio에서 엽니다.
2. Test의 **Server & Clients**를 선택하고 클라이언트 수를 **8**로 설정해 실행합니다.
3. 처음에는 모두 광장에 있으므로 경기가 시작되지 않고 `0 / 8`이 표시되어야 합니다. 다른 창의 캐릭터 움직임이 서로 보이는지 확인합니다.
4. 각 클라이언트의 캐릭터를 북쪽 포털 아래 빛나는 구역에 넣습니다. 7명만 들어갔을 때는 `7 / 8`로 계속 대기해야 합니다.
5. 마지막 1명을 넣으면 `8 / 8`과 카운트다운이 표시되어야 합니다.
6. 카운트다운 중 1명을 구역 밖으로 이동하거나 `대기열 나가기`를 누릅니다. 인원이 감소하고 카운트다운이 취소되어야 합니다.
7. 다시 8명을 넣으면 새 카운트다운이 시작됩니다. 종료 시 **Studio에서 서버 이동 불가 / 대기열 확인 완료** 메시지가 표시됩니다. 이는 오류가 아니라 Studio의 제한입니다.

실제 Roblox `TeleportService`는 Studio 플레이테스트에서 동작하지 않습니다. 서버 이동은 게시된 Experience를 Roblox 앱으로 플레이해야 확인할 수 있습니다. [공식 Teleport 문서](https://create.roblox.com/docs/projects/teleport)

## 2. Studio에서 경기 멀티플레이 확인

1. **`Match.rbxlx`**를 엽니다. 기존 `AutoChess.rbxlx`도 같은 경기 테스트 파일입니다.
2. **Server & Clients → 8 clients**로 실행합니다. Studio에서는 로비에서 이동하지 않아도 경기 서버만 독립적으로 테스트할 수 있습니다.
3. 8명 도착 후 자동 시작되는지 확인합니다.
4. 두 플레이어에서 서로 다른 몬스터를 구매하고 배치합니다.
5. 다른 플레이어의 골드·벤치가 내 구매로 바뀌지 않는지 확인합니다.
6. 준비 시간 종료 후 같은 PvP 짝의 두 창에서 동일한 몬스터 HP, 피해량, 승패를 보이는지 확인합니다. 두 카메라의 시점은 반대입니다.
7. 참가자를 하나 종료하고 나머지 경기가 계속되는지, 생존자가 홀수일 때 야생 대전으로 진행하는지 확인합니다.

Studio는 최대 8개의 테스트 클라이언트를 지원합니다. 동시에 8개 창을 실행하면 PC 자원을 많이 사용하므로 1개 창으로 로비 디자인부터 확인하고, 최종 흐름은 8개로 확인합니다. [공식 Studio 테스트 문서](https://create.roblox.com/docs/studio/testing-modes)

## 3. 실제 별도 서버 이동 확인

1. **같은 Experience 안에 두 Place**를 준비합니다. 로비를 시작 Place로, 경기장을 다른 Place로 둡니다.
2. `src/shared/PlaceConfig.luau`의 `LobbyPlaceId`, `MatchPlaceId`에 해당 **Place ID**를 입력합니다. Experience/Universe ID와 다릅니다. 기본값 `0`인 상태에서는 실제 이동을 하지 않습니다.
3. 저장소 루트에서 `npm run roblox:build`를 실행합니다.
4. 생성한 `Lobby.rbxlx`와 `Match.rbxlx`를 각각 해당 Place에 게시합니다. 두 파일 모두 같은 설정이 들어가야 합니다.
5. 로비 최대 인원은 8명보다 넉넉하게 설정하고 경기 Place는 최대 8명으로 설정합니다.
6. 테스트 참가자 8명이 Roblox 앱으로 **같은 로비 서버**에 접속합니다. 로비에만 서 있으면 이동하지 않아야 합니다.
7. 입장 구역에 모이면 해당 8명만 새 예약 경기 서버로 이동하는지 확인합니다. 이동하지 않은 사람은 로비에 남아 있어야 합니다.
8. 개발자 콘솔에서 경기 Place의 `game.PlaceId`, `game.JobId`, `game.PrivateServerId`를 비교합니다. 동일 경기 참가자들의 서버 ID가 같고, `PrivateServerId`가 비어 있지 않아야 합니다. 콘솔에서 검사할 때 예약 서버 접근 코드는 출력하지 않습니다.
9. 경기 종료 후 로비로 복귀하는지 확인합니다.

일부 참가자의 이동 시작이 실패하면 같은 예약 서버로 최대 3회 재시도합니다. 8명이 경기 서버에 60초 안에 도착하지 못하면 도착한 참가자를 로비로 돌려보냅니다. 이동 실패 메시지와 로비 복귀 버튼도 확인합니다. 플랫폼의 크로스플레이 설정에 따라 같은 예약 서버가 다른 서버 인스턴스로 나뉠 수 있으므로 실제 기기 조합에서도 확인해야 합니다. [공식 TeleportService 문서](https://create.roblox.com/docs/reference/engine/classes/TeleportService)

## 여기서 검증한 범위

- Luau 문법, 프로젝트 XML 구조, 기존 규칙 검사 통과.
- 실제 로비 서버 소스를 모형 서비스에서 실행해 광장 9명은 시작하지 않음, 구역 7명 대기, 8명 카운트다운, 이탈 취소, 해당 8명만 이동 요청, 실패한 사람의 같은 예약 서버 재시도를 검사.
- 실제 Roblox Studio 8개 클라이언트 실행, Roblox 앱의 실제 서버 이동, 화면 검수는 아직 하지 않았습니다.
