# Roblox 포트 — 초기 플레이 기반

원작을 Roblox Luau로 옮기는 별도 프로젝트입니다. **원작 전체를 동일하게 이식한 완성본은 아닙니다.** 웹 서버를 Roblox 안에서 실행하는 방식이 아니라 원작 데이터를 공유하고 Roblox 서버와 클라이언트를 구현합니다. 기존 웹 프로젝트는 그대로 보관합니다.

## 바로 열기

**현재 구조는 자유 탐험 로비와 별도 경기 서버로 분리되어 있습니다. [멀티플레이 확인·게시 안내](MULTIPLAYER-KO.md)를 먼저 읽어주세요.**

- `Lobby.rbxlx`: 광장·상점 설치 자리·경기 입장 구역. 구역에 들어온 8명만 예약 서버로 이동.
- `Match.rbxlx`: 8인 전용 경기 Place.
- `AutoChess.rbxlx`: Match 파일의 호환 이름. 아래 독립 Studio 경기 테스트 설명은 이 파일에 적용됩니다.

로비에 사람이 8명 접속하는 것만으로는 시작하지 않습니다. 로비 서버의 경기 입장 구역에 들어온 사람을 기준으로 하며, Match 독립 테스트의 8명 도착 조건과 다릅니다.

1. Roblox Studio를 설치하고 로그인합니다.
2. 이 폴더의 **`AutoChess.rbxlx`**를 Studio에서 엽니다.
3. Play로 혼자 실행하면 로비 광장을 둘러볼 수 있습니다. **1~7명일 때는 경기를 시작하지 않습니다.**
4. Studio의 **Server & Clients**에서 클라이언트 **8개**로 실행합니다. 8명이 모이면 8초 카운트다운 후 경기장으로 이동합니다. 대기 중 한 명이 나가면 카운트다운을 취소합니다.
5. 상점의 3D 미리보기에서 구매 → 벤치 또는 경기장의 몬스터 선택 → 경기장의 반투명 배치 위치 클릭으로 배치합니다. 몬스터를 선택한 뒤 벤치 버튼을 누르면 벤치로 돌릴 수 있습니다.
6. 25초 뒤 자동 전투가 시작됩니다. 몬스터 이동·공격·투사체·피격 효과·피해 수치·체력바를 3D 경기장에서 표시합니다. 전투 중에는 배치 위치 표시를 숨깁니다.

게시할 Experience의 최대 인원도 8명으로 지정합니다. 서버 코드에도 8명 제한이 있습니다. 자동 시작은 서버에 접속한 8명을 기준으로 하며 별도의 준비 버튼은 없습니다.

두 플레이어는 준비 단계가 끝나면 짝을 이루어 대전합니다. 홀수 플레이어는 야생 보드와 대전합니다. 경기 도중 참가한 사람은 다음 경기부터 참여합니다. 1명의 승자가 남거나 10라운드가 끝나면 경기 종료 후 로비로 돌아갑니다.

실제 Studio 열기·로그인·8클라이언트 대전은 아직 검증하지 않았습니다. 외부 Experience에 게시하지 않았고 Roblox 에셋도 업로드하지 않았습니다. Firebase/MongoDB는 이 Roblox 버전에 필요하지 않습니다. 계정은 Roblox Player를 이용하며 영구 데이터 저장은 아직 없습니다.

## 파일 구성

- `src/shared/Catalog.luau`: 생성된 원작 데이터. 직접 수정하지 않습니다.
- `src/shared/Rules.luau`: 엔진 독립 규칙과 기본 전투.
- `src/server/Main.server.luau`: 서버 권한, 상점, 대전 흐름.
- `src/client/Main.client.luau`: Roblox GUI 및 입력 요청.
- `src/client/ArenaView.luau`: 3D 몬스터·상점 미리보기·전투 시각 효과.
- `src/server/World.luau`: 로비 광장·공중 경기장·플레이어 이동.
- `src/shared/Lobby.luau`: 8명 시작 조건·빈 참가 슬롯 규칙.
- `default.project.json`: Rojo 프로젝트 정의. Rojo는 선택 사항입니다.
- `tools/build-place.cjs`: 추가 라이브러리 없이 `.rbxlx` 생성.
- `tools/export-data.ts`: 고정된 원작 TypeScript 데이터 → Luau 변환.
- `tests/rules.spec.luau`: 소유권·배치·진화·전투·타입 규칙 회귀 검사.

## 수정 후 프로젝트 다시 만들기

저장소 루트에서 실행합니다.

```powershell
npm run roblox:build
```

원작 데이터 변경 후 다시 가져오려면 다음 순서로 실행합니다.

```powershell
npm run roblox:export
npm run roblox:build
```

Studio에서 이전 파일을 저장해 덮어쓰면 소스 폴더에 자동 반영되지 않습니다. 소스 파일을 편집하고 프로젝트를 다시 생성하거나 Rojo로 동기화합니다.

## 검증 결과와 다음 이식 순서

Luau 0.741 문법 컴파일과 엔진 독립 규칙 테스트 통과. Roblox XML 구조 검사 통과. 이는 Roblox 엔진 실행 검증과 다릅니다.

공식 Luau CLI를 `tools/luau/luau.exe`에 준비하거나 `LUAU_BIN` 환경 변수로 경로를 지정한 뒤 `npm run roblox:test`를 실행합니다. 실제 서버 소스를 Roblox 서비스 모형에서 실행하여 7명 대기, 준비 요청 우회 차단, 8명 시작, 9명 거부, 이탈 취소, 재집결, 구매·배치와 전투 진입을 검사합니다. 이 테스트는 실제 Roblox 렌더링과 네트워크를 대체하지 않습니다.

1. Studio 8클라이언트에서 7명 대기→8명 시작→이탈 취소→재참가→구매→3D 배치→전투→결과 확인.
2. 공유 포켓몬 풀, 원작 경제·레벨·PvE 스테이지 이식.
3. 스킬·패시브·시너지·아이템을 원작 코드 단위로 구현하고 비교 테스트.
4. 임시 모델을 완성형 몬스터 모델로 교체하고 이동·스킬 애니메이션 및 모바일 화면 검증.
5. 친구 초대와 방, 재접속, 영구 저장·랭킹 구현 후 게시.

공식 참고: [서버/클라이언트 경계 검증](https://create.roblox.com/docs/scripting/security/client-server-boundary), [Studio 멀티클라이언트 테스트](https://create.roblox.com/docs/studio/testing-modes).
